================================================================================
                        THE 3 CIRCLE METRICS AT A GLANCE
================================================================================

CIRCLE #1: EFFORT SCORE
────────────────────────────────────────────────────────────────────────────
What: Multi-factor effort score (0-100%)
Calculation: Duration + Distance + Pace + Elevation + Heart Rate
Data Needs: distance, duration, heartRate, elevationGain, userAge
Always Shown: YES
Code Location: calculateEffortScore() at line 5973

CIRCLE #2: HR ZONE (preferred) or CADENCE (fallback)
────────────────────────────────────────────────────────────────────────────
Option A - HR ZONE (when heartRate > 0):
  What: Heart rate zone quality (Zone 1-5)
  Calculation: avgHR / maxHR × 100%
  Max HR Formula: 208 - (0.7 × age) [Tanaka method]
  Data Needs: heartRate, heartRateData, userAge
  Zone Quality: Zone 2 (60-70% maxHR) is Excellent

Option B - CADENCE (fallback when HR unavailable):
  What: Cadence quality as % of personalized target
  Calculation: actual / target × 100% (capped at 120%)
  Target Cadence Factors: speed, height, age, weight, incline
  Data Needs: cadence, userHeightCm, userAge, userWeightKg
  Code Location: computeOptimalCadence() at line 6585

CIRCLE #3: CONSISTENCY SCORE
��───────────────────────────────────────────────────────────────────────────
What: Pace consistency via Coefficient of Variation (0-100%)
Calculation: CV of split times; score = (1 - CV×5) × 100%
Data Needs: kmSplits (≥2) OR paceData (≥10)
Shown When: Split or pace data available
Code Location: Built into RunMetricRingsRow() at line 6772

================================================================================
                        DATA FLOW & DEPENDENCIES
================================================================================

Data Sources:
  ├─ RunSession object (from backend API)
  │  ├─ duration, distance, cadence, heartRate
  │  ├─ heartRateData (array of HR samples)
  │  ├─ kmSplits (array of per-km split times)
  │  ├─ paceData (array of pace time-series)
  │  └─ totalElevationGain, totalElevationLoss
  │
  └─ User Profile (from SharedPreferences)
     ├─ age, height (cm), weight (kg)
     └─ [Fallback defaults if not set]

Calculation Order:
  1. Load RunSession from API
  2. Load user profile from SharedPreferences
  3. RunMetricRingsRow() computes:
     ├─ Effort Score (all runs have this)
     ├─ HR Zone (if HR > 0) OR Cadence (fallback)
     └─ Consistency (if split data exists)
  4. MetricRing() renders each metric
  5. Rings animate on load (1200ms)

================================================================================
                          KEY INSIGHTS
================================================================================

1. PERSONALIZATION
   - All metrics personalized to user's age, height, weight
   - Cadence target varies significantly by individual
   - Max HR calculated via Tanaka formula (not fixed)

2. SMART FALLBACK LOGIC
   - HR Zone (preferred) → Cadence (fallback when no HR)
   - Ensures meaningful metric is always displayed
   - Clear data validation before showing rings

3. QUALITY CONSISTENCY
   - All 3 rings use same 5-color palette
   - Quality thresholds consistent across metrics
   - Color = instant visual quality assessment

4. VISUAL DESIGN
   - Canvas-based custom drawing (not built-in components)
   - Donut/progress indicator style (not filled circles)
   - Smooth animation with glow effect
   - Responsive: scales to 1/3 width per ring

5. PERFORMANCE
   - All calculations cached in remember{} blocks
   - Recalculates only when dependencies change
   - Efficient for frequent screen reloads

6. RELIABILITY
   - Multiple fallback strategies for missing data
   - Shows "--" for unavailable metrics
   - Gray ring for no-data state
   - Validates data before calculations
