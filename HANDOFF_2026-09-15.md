## 2. Why the fitness-level work exists

The user noticed many Android users with no `fitness_level`. There are **two separate causes**:

1. **A save race.** `FitnessLevelScreen` called `viewModel.saveFitnessLevel()` (fire-and-forget
   into `viewModelScope`) and navigated in the same click handler. The destination uses
   `popUpTo("fitness_level_onboarding") { inclusive = true }`, which clears the ViewModel and
   **cancels the in-flight PUT**. The local SharedPreferences copy was only written *after* the
   API returned, so a cancelled save lost the answer everywhere. An empty `catch` hid it.
2. **Three bypass routes.** Fitness level had no completion flag of its own — it just sat inside
   the "profile setup" segment. Any user reaching the `needsCoachSetup()`-only state skipped it:
   `RootNavigationGraph.kt` sign-up route, location-permission route, and MAIN landing check.
   Note `clearOnboardingFlags()` (called by the "Take a tour" button) puts users in that state.

iOS had a different bug: it defaulted to `"Regular"`, so users who tapped through were silently
recorded as regular runners — worse than null, because the coach treats it as fact.

## 4. Environment gotchas — these cost real time, don't rediscover them

- **`npm run db:push` is interactive and dangerous here.** It could not tell a new column from a
  rename and offered `apple_account_token › device_manufacturer  rename column`. Piping blind
  Enters into it risks destroying a live column. **Use explicit SQL instead** —
  `ALTER TABLE users ADD COLUMN IF NOT EXISTS <name> <type>` — which is how the five `device_*`
  columns were applied.
- **DB access pattern that works:**
  `node --env-file=.env <script>.cjs` with
  `require('/Users/danieljohnston/AndroidStudioProjects/AiRunCoach/node_modules/pg')` and
  `new pg.Pool({ connectionString: process.env.EXTERNAL_DATABASE_URL, ssl: { rejectUnauthorized: false } })`.
  Scripts in the scratchpad need absolute `require` paths.
- **`swiftc -typecheck` does NOT catch availability errors.** Verified empirically: an
  iOS-17-only `onChange(of:initial:_:)` passed at both `-target ios26.0` and the project's real
  `ios16.6`, while the user's Xcode build rejected it. The harness documented in CLAUDE.md is
  real type-checking but is **blind to availability** — only Xcode catches that class.
  **iOS deployment target is 16.6**; the codebase uses the single-parameter
  `.onChange(of:) { newValue in }` form.
- **`monkeyc` needs `-r`.** Without it the release jungle strips both `:debug` and `:release`
  variants and you get a bogus `Undefined symbol ':_initSimulatorMode'`. Working command:
  `"$SDK/bin/monkeyc" -r -f monkey.jungle -o out.prg -y developer_key.der -d fenix5plus`
  (SDK at `~/Library/Application Support/Garmin/ConnectIQ/Sdks/connectiq-sdk-mac-9.1.0-2026-03-09-6a872a80b`).
  For the store package: add `-e -w` and `-o bin/AiRunCoach-<ver>.iq`, no `-d`.
- **iOS repo commit hygiene.** Last real commit before this session was **2026-03-04**; there are
  ~238 uncommitted entries and ~50 unrelated files pre-staged in the index. **Always commit with
  explicit pathspecs** (`git commit -- "path/a.swift" "path/b.swift"`) so six months of unrelated
  work isn't swept in. Per CLAUDE.md, only commit iOS when the user explicitly asks.
