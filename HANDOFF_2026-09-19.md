## 1. Android trial-expired paywall — "Upgrade to Continue" did nothing — FIXED (`77f1d3f`)

`TrialExpiredWallScreen` is the topmost child of the `Box` wrapping MainScreen's NavHost; the
Upgrade button navigated the NavHost to `subscription` **underneath** the overlay, which stayed
on top. Expired-trial users could never reach the purchase screen. Fix in `MainScreen.kt`: the
wall steps aside while the route is `subscription` / `get_support` / `change_password`, and the
gate is keyed on `subscriptionTierState` so a verified purchase drops it immediately. iOS was
already fine (its wall pushes `SubscriptionScreen` inside its own NavigationStack).

This has been live since the wall shipped — expired-trial users who gave up were never able to
pay. Consider a win-back email to that cohort.

## 2. Apple Watch: Emma Taylor's "can't stop the run" + lost-run sync — FIXED (iOS, uncommitted)

Report: prepared on phone, phone left at home, ran on the watch; watch would only pause/resume,
never stop. Nothing reached the server (0 runs / live sessions / samples for her user
`a3a746b0…`). She's on 1.7.9 (66). Two real bugs:

**(a) Zombie session on the watch** — `WatchWorkoutManager.endWorkout()` was gated on
`isRunning`, which the `HKWorkoutSessionDelegate` clears when watchOS ends the session
underneath us (e.g. Apple's own Workout app starting a run), while `runState` stayed
`.running`. Pause/Resume (gated on `runState`) kept working; End did nothing. Now `endWorkout()`
gates on `runState`, and an externally-ended session is auto-finalised (data saved, DONE screen
with an "Ended by watchOS" note).

**(b) Lost run on reconnect** — if she pressed Start at home (phone in range) the phone
mirrored the workout and claimed ownership at start; on reconnect the watch's sync was acked
and dropped as a "duplicate", the watch deleted its only copy, and the phone's empty mirror was
discarded as too little data. Rewritten so **the watch is always the record** for a mirrored
Apple Watch session:
- `WatchSessionManager.sendWatchEnded()` also queues a durable `workoutEndedQueued` via
  `transferUserInfo` (delivered on reconnect).
- `RunSessionViewModel.endMirrorDeferringToWatch()` — every way a mirror ends (live
  `workoutEnded`, the queued copy, the sync arriving, Stop on the phone) tears the phone session
  down without uploading, hands a `MirrorHandoffContext` (plan/workout ids, coaching notes,
  targets, group/live ids, weather) to `WatchRunSyncManager`, shows the saving overlay, and
  navigates to the summary on `.watchRunSynced`. 60 s fallback uploads the mirror if no sync.
- `WatchRunSyncManager.upload()` builds the run from the watch's full payload, layers the
  context on (linked workout/plan, splits computed from the watch GPS, `wasTargetAchieved`,
  notes), then links live session / completes workout + reassess / closes group run.
- `PhoneSessionManager` no longer prefers phone-accumulated frames over the watch payload.

**Needs a real two-device test before 1.8.3 ships:** start on watch with phone in range →
leave phone → finish out of range → return → expect ONE run with full route + plan linkage,
and the phone's run screen going to that summary. Also: start Apple's Workout app mid-run in
ours → ours should finish itself, not zombie.
